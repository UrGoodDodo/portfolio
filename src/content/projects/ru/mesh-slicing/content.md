## overview

Проект Procedural Mesh Slicing представляет собой **систему разрушения во время выполнения**, разработанную в *Unity*.

Основной целью проекта было создание системы, способной динамически разделять произвольные 3D-меши и одновременно генерировать геометрию для новых поверхностей, появляющихся после разрезания.

Система была разработана в рамках моей работы с **процедурным разрушением и изменением геометрии во время выполнения**.

### Основные цели

Проект был сосредоточен на нескольких ключевых задачах:

- Разрезание мешей во время выполнения
- Поддержка повторных разрезов
- Автоматическое создание поверхностей среза
- Корректная ориентация треугольников
- Поддержка различных материалов

Итоговая система состоит из нескольких взаимосвязанных этапов.

## technical-breakdown

Алгоритм разрезания разделён на несколько этапов.

### 1. Классификация вершин

Каждая вершина классифицируется относительно плоскости разреза.

Вершина может относиться к одной из трёх категорий:

- **Положительная сторона**
- **Отрицательная сторона**
- **На плоскости разреза**

Для предотвращения численной нестабильности используется небольшое значение epsilon.

> Корректная классификация вершин особенно важна, поскольку от неё зависят все последующие этапы алгоритма разрезания.

Упрощённо результат классификации можно представить следующим образом:

```text
distance > epsilon   → Положительная сторона
distance < -epsilon  → Отрицательная сторона
otherwise            → На плоскости
```

### 2. Классификация треугольников

После классификации вершин анализируется каждый треугольник.

Например:

1. Все вершины находятся над плоскостью → треугольник относится к **верхнему мешу**
2. Все вершины находятся под плоскостью → треугольник относится к **нижнему мешу**
3. Вершины находятся по разные стороны плоскости → треугольник необходимо **разделить**

Также необходимо обрабатывать ряд особых случаев:

- одна вершина находится непосредственно на плоскости;
- две вершины находятся непосредственно на плоскости;
- вырожденные пересечения.

### 3. Пересечение рёбер

Когда ребро пересекает плоскость разреза, вычисляется новая точка пересечения.

Чтобы не вычислять одну и ту же точку несколько раз, система использует `EdgeCache`.

Например:

```csharp
if (edgeCache.TryGetValue(edge, out Vector3 point))
{
    return point;
}
```

Это позволяет избежать **дублирующихся вершин** и гарантирует, что соседние треугольники используют одинаковые точки пересечения.

### 4. Восстановление контура

Во время разрезания сохраняются рёбра, образованные в местах пересечения меша с плоскостью.

Затем эти рёбра соединяются в **замкнутые контуры**.

Упрощённо процесс выглядит следующим образом:

```text
Точки пересечения
        ↓
Рёбра контура
        ↓
Замкнутые контуры
        ↓
Геометрия поверхности среза
```

Контур представляет собой границу новой поверхности, появившейся после разрезания объекта.

### 5. Триангуляция поверхности среза

После восстановления контура необходимо закрыть образовавшееся отверстие.

Для этого контур проецируется в двумерное пространство и затем триангулируется.

В текущей реализации используется **алгоритм отсечения ушей (ear clipping)**.

К важным случаям относятся:

- выпуклые вершины;
- вогнутые вершины;
- коллинеарные вершины;
- ориентация треугольников.

## level-design

Хотя проект в первую очередь сосредоточен на **программировании и техническом арте**, получившаяся система разрушения также может влиять на левел-дизайн.

Например, разрушение во время выполнения можно использовать для:

- разрушаемых стен;
- динамических препятствий окружения;
- альтернативных маршрутов игрока;
- интерактивной геометрии уровня.

### Пример использования в геймплее

Представим уровень с двумя возможными маршрутами:

1. Игрок может воспользоваться обычным коридором.
2. Игрок может разрушить часть стены и создать альтернативный проход.

Таким образом, разрушение может стать частью **языка левел-дизайна**, а не использоваться исключительно как визуальный эффект.

## challenges

В процессе разработки возникло несколько технических сложностей.

### Повторное разрезание

Одним из основных требований была возможность повторно разрезать уже разделённые объекты.

Это создаёт дополнительные проблемы:

- ранее созданная геометрия поверхности среза должна сохраняться;
- новые пересечения могут возникать на старых поверхностях среза;
- информация о материалах должна оставаться корректной.

### Вогнутые контуры

Простая веерная триангуляция хорошо работает с выпуклыми многоугольниками, но может создавать некорректную геометрию для вогнутых форм.

По этой причине в проекте был реализован переход к **алгоритму ear clipping**.

### Коллинеарные вершины

Ещё одна проблема возникает, когда несколько вершин контура располагаются почти на одной прямой.

Такие вершины могут приводить к появлению очень маленьких или вырожденных треугольников.

> Это один из примеров ситуации, когда геометрически корректный алгоритм всё равно требует дополнительной устойчивости к численным погрешностям.

## results

Получившийся прототип способен:

- динамически разделять меши;
- генерировать вершины пересечения;
- восстанавливать контуры среза;
- создавать геометрию поверхности среза;
- назначать отдельные материалы новым поверхностям.

### Текущие ограничения

У проекта всё ещё есть несколько направлений для улучшения:

- производительность на очень сложных мешах;
- обработка моделей со сложными внутренними полостями;
- одновременное разрушение большого количества объектов;
- более продвинутые процедурные материалы.

### Дальнейшее развитие

Возможные направления дальнейшей работы:

1. Оптимизация алгоритма разрезания
2. Улучшение упрощения контуров
3. Более устойчивая триангуляция
4. Процедурные материалы для поверхностей среза
5. Интеграция с игровыми системами
